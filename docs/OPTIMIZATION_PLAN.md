数据库版本为 **6**。旧 v4/v5 的升级仪器测试确认历史 ID、正文、时间保留；新原始字节使用 LitePal 支持的 `payloadBase64` 字符串列，公开 API 仍返回 `byte[]`。失败批次重试、终态顺序、删除/滚动保留屏障和全部 256 种字节的往返均有仪器测试。

复查还修复了首页设备资料、Service UUID 和 Debug 宏的主线程数据库访问：后台队列有界，缓存读取不等 LitePal 全局锁，保存成功才更新页面，失败有反馈。服务器打开/关闭监听也移到后台，迟到启动受会话/前台代次检查。实测修正了 LitePal 的 `save()` 不按 `setToDefault()` 清除旧值的问题，清空别名和取消收藏使用明确字段更新。

独立桌面 JVM 分帧基准：64 KiB 输入的累计分配约从 2049 MiB 降至 0.125 MiB，耗时约从 186 ms 降至 1.33 ms；4/16/64 KiB 的分配随输入线性增长。这是同机 JVM 对照，**不是 Android 真机峰值内存或耗时结论**。
